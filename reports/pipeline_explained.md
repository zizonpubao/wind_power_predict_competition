# 파이프라인 상세 해설 — 데이터·피처·판단·모델 (사용자 분석용)

작성: 2026-07-24. 이번 세션의 주요 시도를 "무엇을 왜 어떻게" 관점으로 정리. 각 항목에 실제
코드 위치를 붙였으니 직접 대조하며 분석 가능.

---

## 0. 큰 그림 (한 문단 요약)

원본 예보(LDAPS/GFS 격자) → **격자 집계(IDW)로 그룹별 대표값** → 풍속·파워커브·시간구조 피처 →
**leakage-safe 시계열 CV(발표묶음 단위)로 검증** → **모델(GBM 9분위수 + LSTM + Transformer)** →
**결정이론적 후처리 + 블렌드 + 배수 재보정**. 실전 최고 **0.6280**(원본 v14 0.6362 대비 −0.008,
top-20 목표 0.655엔 미달). 천장 분석 결과 **주어진 예보에서 뽑을 수 있는 신호는 거의 다 뽑았고,
남은 오차는 예보 품질 한계**로 판명.

## 1. 데이터 (원본, `datasets/`, 읽기전용)

| 파일 | 내용 | 핵심 특성 |
|---|---|---|
| `ldaps_*.csv` | KMA 국지예보, **16격자**(~1.5km) | 10m 풍속 u/v, 기온 t2m, 기압 sp, 경계층높이 blh. long format(1시각당 16행) |
| `gfs_*.csv` | NCEP 전지구, **9격자**(0.25°) | 10/80/100m·PBL 풍속 u/v, 일사 dswrf, 운량 tcc |
| `train_labels.csv` | 시간당 발전량 kWh (그룹별) | g1/g2: 2022-24, g3: 2023-24(2022 결측) |
| `scada_*.csv` | 터빈별 10분 출력 | **학습기간만 존재, test엔 없음** → 직접 피처 불가 |

**설비용량**: g1/g2 = 21,600 kWh, g3 = 21,000 kWh. 평가는 **actual ≥ 용량의 10%인 시간만**.

**가장 중요한 함정 (시간 2종)**:
- `forecast_kst_dtm` = 예측 대상 시각
- `data_available_kst_dtm` = 그 예보가 실제로 쓸 수 있게 된 시각(전날 발표)
- 같은 `data_available_kst_dtm`을 공유하는 24시각 = 한 "발표 묶음". **CV는 이 묶음 단위로 끊어야**
  미래정보 누수(leakage)가 안 생김. (loader: `src/data/loaders.py`)

## 2. 피처 엔지니어링 (`src/features/`)

### 2.1 공간 집계 — 격자 → 그룹 대표값 (`weather_features.py::spatial_aggregate`)
16/9개 격자값을 각 그룹 **터빈 무게중심 좌표**(`_group_centroid`, `docs/info_raw.csv`의 터빈
GPS 평균) 기준으로:
- **IDW**(역거리제곱 가중, `weight = 1/거리²`) → `{col}_idw`
- **최근접 격자** → `{col}_nearest`

왜: 모델 입력은 1시각당 1행이어야 하는데 원본은 격자당 1행(long). 터빈 위치에 가까운 격자에
가중치를 더 줘서 대표 풍속을 만듦. **LDAPS(1.5km)가 GFS(0.25°)보다 풍속-발전 상관이 높아
주피처**(0.73 vs 0.55).

### 2.2 풍속·풍향·파워커브
- `wind_speed_direction`: u/v → 풍속 √(u²+v²), 풍향 sin/cos/deg.
- `power_curve_transform`: 풍속 → 정규화 파워커브 출력[0,1] (터빈 cut-in/rated/cut-out 반영).
  발전량이 풍속에 선형이 아니라 **S자(cut-in 3m/s 이하 0, rated 12m/s 이상 포화)**라, 이 비선형을
  피처로 미리 넣어 트리가 쉽게 학습하게 함.

### 2.3 시간 구조 (`lag_rolling_features`)
발표묶음 내에서 풍속/파워커브의 **3/6/12/24h 롤링 평균·표준편차**. 예보의 추세·변동성 포착.

### 2.4 추가 시도한 피처 (이번 세션) — **대부분 무효**
| 피처 | 파일 | 결과 |
|---|---|---|
| 웨이크(g1→g2 후류) | `wake_features.py` | g2 소폭↑, **채택** |
| 허브높이 외삽·캘린더·lead_hours (Phase A) | `wind_shear.py`, `calendar_features.py` | CV 악화, **미채택**(코드만 유지) |
| 공기밀도 ρ, ρv³, 전단, 풍향섹터, 격자분산, SCADA파워커브 | `physics_features.py`, `scada_power_curve.py` | 노이즈, g2 미세↑, **미채택** |

### 2.5 피처 선택 (pruning, `feature_selection.py`)
전체 ~141개 → **gain 기준 95% 누적**으로 그룹별 ~65개로 축소(`configs/selected_features.json`).
과적합 위험(141피처 vs 2만행) 줄이기 목적. 실제 효과는 미미(+0.0006)했으나 무해.

## 3. 검증 방법 = "무엇이 진짜인지 판단하는 기준" (핵심)

### 3.1 leakage-safe CV (`src/validation/splitter.py::BlockTimeSeriesSplit`)
- `data_available_kst_dtm` 블록 단위로 정렬 → 5개 fold, **expanding window**(fold k 검증 = 청크 k,
  학습 = 청크 0..k-1). 발표묶음이 fold 경계를 넘지 않게 해서 미래→과거 누수 차단.
- **직접 train_test_split 금지** — 반드시 이 분할기 사용.

### 3.2 공식 점수 (`src/evaluation/metrics.py::competition_score`)
```
score = 0.5·(1-NMAE) + 0.5·FICR
NMAE  = 평균(|예측-실제| / 설비용량)
FICR  = Σ(단가_h·실제_h) / Σ(4원·실제_h)   단가: 오차율≤6%→4원, 6~8%→3원, >8%→0원
```
- **FICR은 계단(불연속) 지표** — 오차율이 6%/8% 문턱을 넘느냐가 3%→5% 개선보다 훨씬 중요.
- **적격 시간(actual≥10%용량)만** 채점.

### 3.3 판단 규칙 (이번 세션에서 확립한 것)
1. CV 개선이 **fold 표준편차(~0.02) 노이즈밴드를 넘어야** 진짜로 간주.
2. **그러나 CV가 실전을 자주 배신함** — 이게 이번 세션 최대 교훈. 예:
   - CV로 최적화한 블렌드 가중치(nested-LOFO)가 실전에서 **단순 고정 가중치한테 짐**.
   - OOF 최적 배수(full)가 실전에서 **과보정**, 절반(half)이 최적.
3. 그래서 **원리적으로 단순·견고한 것을 신뢰**하고, 최종 판단은 리더보드로. 유연한 보정(isotonic
   등)은 fold 노이즈에 과적합해서 실전 전이 실패.

## 4. 모델 구성 (`src/models/`, `src/training/`)

세 모델을 **그룹별로 따로** 학습(g1/g2/g3 데이터·특성이 달라서).

### 4.1 GBM 9분위수 + 결정이론 (가장 강력, `lgbm_quantile_model.py` + `decision_optimize.py`)
- **9개 LightGBM 분위수 회귀**(objective="quantile", alpha=0.05,0.15,…,0.95) → 각 시각의 발전량
  **분포**를 얻음.
- **결정이론적 후처리**: 그 분포로 pmf를 만들고, 0~용량 격자 중 **공식 점수(1-NMAE+FICR)의
  기대효용을 최대화**하는 점을 선택. 즉 "평균/중앙값"이 아니라 **FICR 계단을 직접 겨냥**해 점 예측.
- 왜 강한가: FICR이 계단 지표라, 단순 오차 최소화보다 "6%/8% 문턱을 넘길 확률을 높이는" 결정이
  돈이 됨. **단일 최강**(CV 0.6038, 실전 0.6126).

### 4.2 LSTM (`lstm_model.py`, `torch_common.py`)
- **양방향 seq2seq**: 발표묶음 24시간을 한 번에 보고 24시간 발전량을 동시 예측(단일시각 예측이
  아님). 6개 시드 배깅 평균, g3만 mixup 증강.
- 시퀀스 단위를 **발표묶음(달력 하루 아님)**으로 끊어 CV fold와 정확히 일치 → leakage 없음.
- CV 0.5953 (GBM보다 약하지만 오차 패턴이 달라 블렌드에 기여).

### 4.3 Transformer (`transformer_model.py`)
- 2층 인코더 + sinusoidal 위치인코딩, 4시드 배깅, 점추정. LSTM과 같은 시퀀스 인프라 재사용.
- CV 0.5963.

### 4.4 그 외 (블렌드 미채택)
XGBoost/CatBoost(약함), 비대칭손실 LightGBM(과소예측 페널티 — 결정단계가 이미 흡수),
FICR-surrogate 손실(절벽항이 오히려 예측 교란, 실패).

## 5. 앙상블 + 후처리 (`src/ensembling/`) — 점수 상승의 실제 원천

### 5.1 블렌드 (`blend_search.py`)
- **v14 고정 가중치**: 최종예측 = 0.35·LSTM + 0.35·Transformer + 0.30·GBM (점추정 가중평균).
- 실전 0.6227. 신경망이 단독으론 약해도 **다양성**으로 GBM 단독(0.6126)보다 +0.010.
- ⚠️ CV로 가중치를 최적화(nested-LOFO)했더니 실전에서 이 단순 고정값한테 **졌음** → 교훈.

### 5.2 배수 재보정 (`recalibrate.py`) — 세션 최고 발견
- 진단: 예측이 **전 구간 체계적으로 6~12% 낮음**(모델이 평균으로 회귀).
- 처방: 그룹별 **단일 배수**로 예측을 위로 스케일. `applied = 1 + strength·(oof최적배수 - 1)`.
- **강도 절반(0.5)**이 실전 최적(full은 과보정). 왜 절반? OOF는 폴드별 4/5 데이터 모델이라 실제
  refit보다 편향을 과대추정.
- 실전 0.6227 → **0.6280 (신규 최고)**. 예전 g2 isotonic 보정은 실패했는데 **단일 배수는 과적합
  불가라 g2 포함 전 그룹 성공** — "유연함=과적합=실전실패" 교훈의 반례.

## 6. 왜 여기서 막혔나 — 천장 분석 (2026-07-24)

`scratchpad/ceiling_analysis.py`로 확인:
- 우리 모델 NMAE **13~15%** vs "예보풍속만 쓴 오라클" 17% → **우리가 이미 2.4~3.6%p 더 정확**
  (풍속 외 신호를 잘 쓰고 있음, 모델 문제 아님).
- 같은 예보풍속 bin 안에서 실제 발전량이 **±20% 산포** → **예보풍속이 실제 발전을 잘 결정 못 함**
  = 예보 자체의 한계.
- bin내 잔여를 설명하는 변수(grid_std 0.4, dswrf, blh)는 **이미 모델에 들어있음** → 물리피처
  재추가가 노이즈였던 이유.

**결론**: 주어진 LDAPS/GFS에서 **추출 가능한 신호는 거의 다 뽑았다.** 남은 오차는 예보 품질
한계라 후처리·피처·튜닝으로 못 넘음. 상위팀과의 갭(특히 FICR)은 **더 나은 예보**(ECMWF 등)에서
올 가능성이 큼 — 근데 무료 ECMWF 예보 아카이브가 2024-05부터라 학습기간 커버가 얇음(미해결).
